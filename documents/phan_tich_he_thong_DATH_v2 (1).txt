1. TỔNG QUAN DỰ ÁN
1.1 Mục tiêu
Xây dựng hệ thống web quản lý toàn bộ quy trình Đồ án Tốt nghiệp (ĐATN) thay thế việc quản lý thủ công bằng file Excel/Google Sheets hiện tại. Hệ thống hỗ trợ 3 nhóm người dùng: Admin, Giảng viên hướng dẫn (GVHD), và Sinh viên.
 
1.2 Phạm vi hệ thống
Khía cạnh	Mô tả
Đối tượng	Admin (PĐT), Giảng viên hướng dẫn, Sinh viên
Phạm vi	Quản lý từ đầu kỳ đến khi hoàn tất bảo vệ ĐATN
Khóa học	Hỗ trợ đa khóa: K2024, K2025, K2026,...
Công nghệ	Laravel (PHP), MySQL, giao diện web responsive
File hỗ trợ	Import/Export Excel (.xlsx), nộp Word/PPT/PDF
 
1.3 Dữ liệu thực tế hiện có
Dựa trên dữ liệu hiện có trong hệ thống:
•	DANHSACHLOP.xlsx: Danh sách sinh viên đăng ký môn học (IE400.F2.CN2.CNTT) — tổng ~74 sinh viên
•	DANHSACHDETAI.xlsx: Danh sách 74 đề tài đã đăng ký, bao gồm nhóm (2 SV) và cá nhân
•	Dữ liệu mẫu gồm 2 nhóm khóa: 242xxxxx (K2024) và 254xxxxx (K2025)

4. USE CASE CHI TIẾT
4.1 Module Admin
UC-A01: Import danh sách sinh viên (Mẫu 1)
Thuộc tính	Nội dung
Actor	Admin
Mô tả	Import file Excel Mẫu 1 để tạo danh sách SV và tài khoản tự động
Điều kiện tiên quyết	Admin đã đăng nhập, file Excel đúng cấu trúc Mẫu 1
Luồng chính	1. Admin chọn khóa học → 2. Upload file Excel → 3. Hệ thống validate → 4. Tạo bản ghi students + users → 5. Hiển thị kết quả

Luồng ngoại lệ	File sai cấu trúc → báo lỗi. MSSV đã tồn tại → bỏ qua / cập nhật (có option chọn)
Output	Danh sách SV được tạo + tài khoản mặc định (MSSV = username, password = MSSV hoặc ngày sinh)
 
UC-A02: Import danh sách đề tài do SV đã đăng ký (Mẫu 2)
Thuộc tính	Nội dung
Actor	Admin
Mô tả	SV tự nhập thông tin đề tài trực tiếp trên hệ thống web (tên đề tài TV, TA, GVHD). Admin xem lại và import/cập nhật vào hệ thống từ file tổng hợp Mẫu 2. Nếu SV nhập sai chính tả, chỉ Admin có quyền sửa.
Cấu trúc Mẫu 2	STT | Thông tin SV (MSSV_Họ Tên SV1 - SV2) | GVHD | Tên đề tài TV | Tên đề tài TA | Đơn đăng ký (link) | Đề cương word (link) | Đề cương pdf (link)
Luồng chính
1. SV đăng nhập → nhập tên đề tài TV, TA → chọn GVHD → submit. 2. Admin xem danh sách đề tài SV đã nhập → import/xác nhận vào hệ thống từ Mẫu 2. 3. Nếu SV nhập sai chính tả: Admin vào sửa tên đề tài → lưu lại. Hoặc có thể tải lên hệ thống đúng theo mẫu 2
Output	Danh sách đề tài hiển thị trên hệ thống. Có thể xuất lại Mẫu 2.
 
UC-A03: Xem báo cáo & Xuất dữ liệu
Chức năng	Mô tả
Báo cáo Mẫu 3	Ai đã có / chưa có đề tài. Nhóm 2 SV hiển thị thành 2 dòng riêng biệt. Lọc theo khóa học, lớp.
Xuất Mẫu 4	Danh sách đầy đủ xuất về PĐT. Mỗi SV 1 dòng riêng. Gồm: STT, MSSV, Họ, Tên, Tên đề tài TV, TA, GVHD, CBPB, Nhận xét CBPB.
Xuất Mẫu 2	Xuất lại danh sách đăng ký đề tài theo định dạng Mẫu 2 (có header tím, tiêu đề học kỳ)
 
UC-A04: Duyệt file sinh viên
Giai đoạn	Người duyệt	Hành động
Đầu kỳ	Admin	Duyệt đơn đăng ký và đề cương. Có thể Approve / Reject kèm ghi chú.
Giữa kỳ	Admin	Duyệt bản chỉnh sửa khi Admin yêu cầu. Chỉ mở khi Admin cho phép.
Cuối kỳ	Admin + GVHD	Duyệt báo cáo trước và sau bảo vệ. Cả Admin và GVHD đều duyệt (sequential hoặc parallel).
 
4.2 Module Giảng viên (GVHD / GVPB)
UC	Mô tả
GV-01	Đăng nhập bằng tài khoản do Admin cấp
GV-02	Xem danh sách nhóm SV được phân công hướng dẫn. KHÔNG xem được nhóm của GV khác.
GV-03	Duyệt file SV nộp ở giai đoạn cuối kỳ (trước và sau bảo vệ): Approve / Reject + ghi chú
GV-04	Xem thông tin đề tài của các nhóm mình phụ trách
GV-05 (GVPB)	Nhập nhận xét phản biện cho nhóm được giao. Nhận xét này được xuất theo Mẫu 4.
 
4.3 Module Sinh viên
UC	Mô tả
SV-01	Đăng nhập bằng MSSV + mật khẩu (mật khẩu do Admin tạo từ Mẫu 1, SV có thể đổi sau)
SV-02	Nhập thông tin đề tài: tên đề tài tiếng Việt, tên đề tài tiếng Anh, chọn GVHD từ danh sách
SV-03	Xem & kiểm tra thông tin đề tài: tên thành viên nhóm, tên đề tài TV và TA đã đúng chưa
SV-04	Nộp file Đầu kỳ: đơn đăng ký ĐATN + đề cương (Word/PDF)
SV-05	Nộp file Giữa kỳ: bản chỉnh sửa (khi Admin yêu cầu chỉnh sửa)
SV-06	Nộp file Cuối kỳ: báo cáo trước bảo vệ + báo cáo sau bảo vệ
SV-07	Xem trạng thái duyệt file của từng giai đoạn (Chờ duyệt / Đã duyệt / Từ chối + lý do)
SV-08	Xem nhận xét của GVPB sau khi giảng viên đã nhập
SV-09	Xem thông tin GVHD và GVPB phụ trách nhóm mình
 
5. QUY TRÌNH NỘP FILE & DUYỆT CHI TIẾT
5.1 Ba giai đoạn nộp file
Giai đoạn	Mô tả	Loại file	Người duyệt	Ghi chú
(1) Đầu kỳ	Nộp đơn đăng ký ĐATN và đề cương	Word, PDF, PPT	Admin	Mở ngay đầu kỳ
(2) Giữa kỳ	Nộp bản chỉnh sửa khi Admin yêu cầu	Word, PDF, PPT	Admin	Chỉ mở khi có yêu cầu
(3) Cuối kỳ — Trước bảo vệ	Nộp báo cáo hoàn chỉnh trước khi bảo vệ	Word, PDF, PPT	Admin + GVHD	
(3) Cuối kỳ — Sau bảo vệ	Nộp báo cáo đã chỉnh sửa sau bảo vệ	Word, PDF, PPT	Admin + GVHD	
 
5.2 Trạng thái file
•	pending: Đã nộp, chờ duyệt
•	approved: Đã được duyệt
•	rejected: Bị từ chối — kèm lý do. SV có thể nộp lại.
•	re_submitted: Đã nộp lại sau khi bị từ chối

8. YÊU CẦU PHI CHỨC NĂNG & LƯU Ý
8.1 Bảo mật
•	Phân quyền bằng Laravel Gates / Policies theo role (admin, gvhd, gvpb, student)
•	Mỗi GV chỉ truy cập được dữ liệu nhóm mình phụ trách (Row-level security)
•	Mật khẩu được hash bằng Bcrypt (Laravel mặc định)
•	CSRF protection cho tất cả form (Laravel mặc định)
•	Validate file upload: chỉ cho phép Word (.docx), PDF (.pdf), PowerPoint (.pptx), giới hạn dung lượng
 
8.2 Hiệu năng & Khả năng mở rộng
•	Hỗ trợ đa khóa học: thêm academic_year_id vào tất cả bảng liên quan
•	Index database trên các cột tìm kiếm thường xuyên: mssv, academic_year_id, group_id, status
•	Sử dụng Eager Loading (with()) để tránh N+1 query
•	Export Excel dùng chunk processing với Laravel Excel (Maatwebsite) khi dữ liệu lớn
 
8.3 Ghi chú triển khai
•	(Làm sau - chưa gấp): Cập nhật danh sách hội đồng bảo vệ
